# Semantic Sticker 普通 NA 用户后台访问设计

- 日期：2026-08-19
- 状态：已获用户确认
- 目标分支：`codex/semantic-sticker-active-user-auth`

## 背景

当前插件的 `/api/*` 路由使用 NekroAgent 的 `get_current_super_user` 依赖。它会先验证 NA 登录 Token，再额外要求超级管理员权限，导致普通但已登录 NA WebUI 的用户进入表情包后台时收到 HTTP 403。

NekroAgent 的插件路由挂载层只负责检查插件是否启用，不会自动为插件路由增加登录认证。因此不能删除 API 依赖；否则未登录请求也可能直接访问插件数据和管理操作。

## 目标

任何已经通过 NA WebUI 登录且账号处于启用状态的用户，都可以访问表情包 WebUI 的全部功能，包括：

- 查看统计、表情包列表、元数据和预览；
- 上传表情包；
- 编辑标签和元数据；
- 删除单个或批量表情包；
- 重分析、重建单个向量和全量重建向量。

未登录或 Token 失效的请求仍必须被 NA 认证依赖拒绝，返回 HTTP 401。插件不再要求超级管理员权限。

## 方案

将插件 API 的依赖从 `get_current_super_user` 改为 NekroAgent 的 `get_current_active_user`。该依赖保留 NA JWT 登录和账号启用检查，但移除超级管理员等级检查。

实现要点：

1. `build_router()` 默认使用 `get_current_active_user`。
2. `/api/*` 仍统一绑定认证依赖，避免任何接口意外变成公开接口。
3. 写操作继续从认证依赖返回的 NA 用户对象读取 `username`，作为服务层审计 actor；不接受请求体或查询参数传入的 actor。
4. 保留已有的 `?token=` 兼容入口、同源 `auth-storage` Token 读取和请求 Authorization Header 注入。
5. 前端移除“超级管理员权限不足”这一不再适用的专门状态文案；若后端仍返回 403，按通用服务错误展示。
6. 同步更新测试、README、用户手册和 CHANGELOG，明确权限边界。

## 不采用的方案

### 完全删除 API 鉴权

不采用。插件路由挂载层不负责用户认证，删除依赖会让未登录用户能够直接调用读取和写入接口。

### 插件自行解析 Token

不采用。重复 NA 的 JWT 校验逻辑会造成维护分叉，并可能与 NA 的 Token 生命周期或用户状态判断不一致。

## 验收标准

- 未提供有效 NA Token：插件页面静态外壳可以加载，所有 `/api/*` 请求返回 401。
- 已登录普通用户：统计、列表、预览、上传、编辑、删除、重分析、重建向量全部成功。
- 已登录超级管理员：现有行为保持不变。
- 普通用户的服务层 actor 等于认证用户的 `username`，伪造请求中的 actor 不生效。
- 前端不再显示“当前账户缺少超级管理员权限”作为正常访问门槛。
- 全量测试通过，且 Git diff 仅包含本次权限调整、文档和测试变更。
