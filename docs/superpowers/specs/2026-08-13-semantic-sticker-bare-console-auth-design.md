# Semantic Sticker 裸地址控制台鉴权设计

- 日期：2026-08-13
- 仓库：`Akiyo-dayo/nekro-plugin-semantic-sticker`
- 插件 ID：`Akiyo.semantic_sticker`
- 目标路径：`/plugins/Akiyo.semantic_sticker/`
- 实施边界：只修改插件，不修改 NekroAgent（NA）或 NUP 项目

## 1. 背景与问题

当前插件在 `build_router()` 创建顶层 `APIRouter` 时同时挂载了查询参数 Token 提升依赖和 `get_current_super_user`：

```python
APIRouter(
    dependencies=[
        Depends(_promote_query_token),
        Depends(get_current_super_user),
    ],
)
```

因此，浏览器直接请求控制台裸地址时，首个 HTML 请求尚未执行插件前端 JavaScript，服务器就要求该请求携带 Bearer Token。NA 的登录状态虽然保存在同源浏览器存储中，但普通地址栏导航不会自动把该 Token 放入 `Authorization` 请求头，最终返回 HTTP 401。

现有 NUP 集成可以通过 `?token=` 入口打开，是因为插件的 `_promote_query_token` 会先把查询参数提升为 Bearer Header。该兼容路径需要保留。

## 2. 目标

1. 已在同一 NA 实例登录的超级管理员，直接输入以下裸地址即可进入控制台：

   ```text
   /plugins/Akiyo.semantic_sticker/
   ```

2. 不修改 NA 前后端源码、鉴权逻辑或路由。
3. 不降低插件管理 API 的权限要求，所有数据读取和管理操作仍仅限 NA 超级管理员。
4. 保留 NUP 的 `?token=` 入口兼容性。
5. 未登录或 Token 失效时留在插件页面，显示提示和“前往 NA 登录”按钮，不自动跳转。
6. 已登录但不是超级管理员时明确显示权限不足，不形成登录跳转循环。

## 3. 非目标

- 不把控制台管理 API 改为匿名可访问。
- 不在插件内维护独立管理员账户、密码或长期会话数据库。
- 不修改 NA 的 `auth-storage` 内容或退出登录行为。
- 不在本次代码工作中部署、重启或热更新任何生产 NA 实例。
- 不承诺跨域、跨子域、跨端口复用 NA 登录态；浏览器同源规则仍然适用。

## 4. 方案比较

### 4.1 采用：公开静态控制台外壳，API 继续鉴权

首页和静态资源允许匿名获取。页面运行后，从查询参数、插件标签页会话存储或同源 NA 登录存储中取得 Token，再以 Bearer Header 请求受保护 API。

优点：

- 修改范围只在插件；
- 满足裸地址访问；
- 数据和管理能力的服务端权限边界不变；
- 保留 NUP 现有访问方式；
- 无需新增服务器端状态。

代价：

- 依赖 NA 当前使用的 `localStorage["auth-storage"]` 键名及其持久化结构；
- 仅在插件页面与 NA WebUI 同源时生效。

### 4.2 不采用：插件建立独立 HttpOnly Cookie 会话

需要增加 Token 交换、服务器端会话、Cookie 生命周期、CSRF 防护和登出同步。复杂度与维护成本明显高于本次需求，且仍要解决插件会话与 NA 用户身份的可信映射。

### 4.3 排除：取消整个控制台鉴权

这会公开表情包清单、原图、上传、删除、编辑和索引重建能力，违反权限边界，不可接受。

## 5. 路由与服务端设计

### 5.1 公开路由

以下路由不再执行 `get_current_super_user`：

- `GET /`
- `GET /static/{path:path}`

它们只能返回仓库内白名单静态文件或内联后的 HTML、CSS、JavaScript，不调用插件服务，不读取统计数据、表情包元数据、缩略图或原图。

查询 Token 提升依赖 `_promote_query_token` 继续保留在顶层路由，以兼容 `?token=` 并在服务端解析请求时移除查询参数。首页公开后，该依赖只负责验证和规范化显式提供的 Token，不再强制要求每次首页请求都存在 Token。

### 5.2 受保护 API

所有 `/api/*` 路由继续要求 `get_current_super_user`。实现时优先建立统一的受保护子路由：

```python
api_router = APIRouter(
    prefix="/api",
    dependencies=[Depends(auth_dependency)],
)
```

所有 API 声明迁移到该子路由，最后由顶层路由 `include_router(api_router)`。这样权限边界由统一结构保证，避免以后新增接口时遗漏逐路由鉴权。

现有写操作中用于获取操作者用户名的 `Depends(auth_dependency)` 可以保留，以便把已认证用户对象传给 `_actor()`；FastAPI 会在同一请求依赖图中复用依赖结果。只读接口则由子路由统一依赖保护。

### 5.3 查询 Token 兼容

`?token=` 仍具有最高优先级：

- 支持裸 Token 和 `Bearer ` 前缀；
- Token 格式不合法时返回 HTTP 401；
- 从请求查询字符串中移除 `token`，保留其他查询参数；
- 生成或覆盖本次请求的 `Authorization: Bearer ...`；
- 前端启动后也会把 Token 保存到当前标签页会话存储，并清理浏览器地址栏中的敏感查询参数。

## 6. 前端登录态设计

### 6.1 Token 来源和优先级

页面启动时按以下优先级解析：

1. 当前 URL 的 `?token=`；
2. `sessionStorage["na_console_token"]`；
3. 同源 `localStorage["auth-storage"]` 中的 `state.token`。

有效 Token 会去除可选的 `Bearer ` 前缀，并写入当前标签页的 `sessionStorage["na_console_token"]`。插件不会改写或删除 `localStorage["auth-storage"]`。

### 6.2 安全解析 NA 登录存储

读取 `auth-storage` 必须满足：

- 使用 `try/catch` 包围浏览器存储访问和 JSON 解析；
- 仅接受对象结构中的非空字符串 `state.token`；
- 缺少键、JSON 损坏、结构未知、Token 为空或存储访问被浏览器禁止时，均按“没有可用登录态”处理；
- 不把 Token 拼入可见文本、错误信息、日志或 DOM；
- 不读取 `userInfo` 来替代服务端权限判断。

NA 的本地 `userInfo` 只属于客户端缓存，超级管理员资格仍由每次 API 请求中的 `get_current_super_user` 在服务端判定。

### 6.3 API 请求和一次性恢复

共享 `api()` 请求函数继续为所有数据、预览和管理请求添加 Bearer Header。

若使用现有会话 Token 请求返回 HTTP 401：

1. 从当前 NA `auth-storage` 重新读取一次 Token；
2. 只有新 Token 存在且与失败 Token 不同时，更新插件会话 Token并重试原请求一次；
3. 禁止无限重试；第二次仍为 401 时进入未登录状态。

该机制处理“插件标签页保存了旧 Token，但用户已在 NA 重新登录”的情况。HTTP 403 不触发 Token 重试或登录跳转。

## 7. 页面状态与交互

页面增加明确的访问状态层，并在认证成功前不加载或启用管理功能。

### 7.1 已认证超级管理员

- 首个受保护 API 请求成功；
- 隐藏访问提示；
- 正常加载统计、表情包列表和现有管理控件。

### 7.2 未登录或登录失效（HTTP 401）

- 停止后续初始化数据请求和轮询；
- 清除无效的插件 `sessionStorage["na_console_token"]`，但不修改 NA 的 `auth-storage`；
- 隐藏或禁用上传、编辑、删除和索引操作区域；
- 显示“请先登录 NekroAgent 后再访问此控制台”；
- 显示“前往 NA 登录”按钮，链接到同源 `/#/login`；
- 不自动跳转，用户登录后可返回并刷新裸地址。

### 7.3 权限不足（HTTP 403）

- 显示“当前账户不是超级管理员，无权访问此控制台”；
- 隐藏或禁用所有管理控件；
- 不清除 NA 登录态；
- 不自动跳转登录页，也不重复尝试请求。

### 7.4 其他错误

现有网络和 HTTP 状态提示继续生效。401 与 403 必须使用不同中文文案，避免把权限不足误报成登录失效。

## 8. 安全边界

1. 匿名用户最多获得无业务数据的静态控制台外壳。
2. 表情包元数据、统计、缩略图、原图和所有写操作仍由服务端超级管理员依赖保护。
3. Token 不写入 Cookie、服务器端文件、日志、页面源码或可见错误信息。
4. URL Token 读取后立即通过 `history.replaceState` 清理，且不保留在历史记录的新条目中。
5. 不信任客户端声明的角色；权限以 API 的实际 401/403 响应为准。
6. 静态资源路由继续使用固定白名单和路径边界校验。
7. Token 恢复最多重试一次，防止请求循环和重复写操作风险。对非幂等写请求不得在收到 401 后自动重放，只有初始化阶段的只读探测允许恢复后重试；用户发起的写操作应提示重新登录后手工重试。

## 9. 测试策略

实施采用测试驱动开发，先添加失败测试，再修改生产代码。

### 9.1 路由测试

- 匿名 `GET /` 返回 200 且包含内联页面资源；
- 匿名访问白名单静态资源返回 200；
- 未认证访问每一个 `/api/*` 路由仍返回 401；
- 普通已登录用户访问 API 返回 403；
- 超级管理员访问全部 API 保持成功；
- `?token=` 仍在鉴权前提升为 Bearer Header，并从查询范围移除；
- 路由清单检查确保所有 `/api/*` 都继承统一超级管理员依赖。

### 9.2 前端静态契约测试

- Token 来源包含查询参数、插件 `sessionStorage` 和 NA `auth-storage`；
- Token 优先级符合设计；
- `auth-storage` 使用异常安全的 JSON 解析并校验 `state.token`；
- URL Token 使用后被清理；
- 401 与 403 文案和状态分离；
- 未登录状态包含同源 `/#/login` 按钮；
- 所有 API 和预览仍经过共享鉴权请求函数；
- 前端不显示、记录或插入 Token；
- 自动重试仅限安全只读请求且最多一次。

若现有测试体系适合执行 JavaScript，可把 Token 解析拆成无 DOM 副作用的小函数并进行行为测试；否则至少以静态契约测试锁定关键安全结构，并通过浏览器验收覆盖运行行为。

## 10. 浏览器验收

在不修改 NA 代码的前提下，使用同源 NA 页面验证：

1. 超级管理员已登录，直接在地址栏输入裸控制台地址，页面正常加载数据；
2. 未登录访问裸地址，页面返回 200，只显示登录提示和按钮，API 请求无数据泄漏；
3. 普通用户已登录，页面显示超级管理员权限不足；
4. NUP 的 `?token=` 入口继续可用，地址栏 Token 被清理；
5. 匿名直接请求列表、统计、预览和写操作 API，均被拒绝；
6. 浏览器存储中的 `auth-storage` 损坏时，页面稳定进入未登录状态；
7. 插件会话 Token 过期而 NA 存储已有新 Token 时，只读初始化可恢复一次；
8. 写操作遇到 401 时不自动重放。

生产实例上的浏览器验收、部署和重启必须另行获得明确授权。
